**Anthropic API access is blocked until 2026-09-01 00:00 UTC.** A console spend
limit was applied retroactively over August's existing ~$40 of usage. Raising it
to $11 did not clear it; August's real spend is higher.

So during market hours, once bars are fresh and the stale gate stops absorbing
triggers, the operator WILL attempt a model call and get:

```
400 invalid_request_error: You have reached your specified API usage limits.
```

That surfaces as `!! OPERATOR RUN FAILED` in the tick log and a non-zero tick
exit. **This is expected and it is not a regression.** The judgment lane is
down; everything else runs.

To restore judgments today: `console.anthropic.com` → **Usage** → read August's
actual spend → set the limit above it. The money is already spent; the limit is
only blocking future calls, which are capped locally at $0.30/day anyway.

## Running reads by hand while the API is down

```bash
python3 daytrade/manual_read_lane.py emit --symbol NVDA --since-hours 12
```

Prints a prompt packet from the archive — headlines, publishers, descriptions,
with Polygon's sentiment deliberately stripped so your read isn't anchored.
Paste into Claude Code, record the result back.

It lands in `data/daytrade/manual_reads.jsonl` with `mr-` ids and full
provenance. **It cannot enter the scoring apparatus** — a manual read has no
`scenario_probs` and no expected-R band, so it is unrepresentable as a forecast.
That boundary is what keeps the Brier score meaningful. Don't route around it.
